The instance can now tell visitors apart behind a CDN or a load balancer. Name the proxies in front of it with `OPENOKR_TRUSTED_PROXIES` (Helm: `network.trustedProxies`), as addresses or CIDR ranges, and `X-Forwarded-For` is read from the right past them; or, behind a CDN that is the only way to reach the server, name the one header it writes with `OPENOKR_CLIENT_ADDRESS_HEADER` (`network.clientAddressHeader`), such as `cf-connecting-ip`. Every per-address limit, the sign-in hold, the session list and the `auth.rate_limited` row then count the visitor rather than the proxy. **Behaviour changes with nothing set: `X-Real-IP` is no longer read as a fallback**, because a proxy that appends to `X-Forwarded-For` leaves it as the caller sent it, which let a caller choose their own address. The Compose install sees no difference; a proxy that writes only `X-Real-IP` is named with `OPENOKR_CLIENT_ADDRESS_HEADER=x-real-ip`. A malformed entry, `0.0.0.0/0`, or both variables set refuse the boot naming the entry, and the chart refuses the same. The boot log says which reading is in force, a change of it writes `instance.caller_address_configured` to the instance audit chain, `openokr_caller_addresses_total` counts placed and unplaced callers, and Admin, General on a self-hosted instance says when the instance has met a visitor it could not place. On Compose, `./openokr up` hands the same list to Caddy. `docs/install/behind-a-proxy.md` says what to set for each setup.
