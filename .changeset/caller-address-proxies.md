The instance can now tell visitors apart behind a CDN or a load balancer. By default the visitor is the `X-Forwarded-For` entry one place from the right, the one the nearest proxy wrote, and `OPENOKR_TRUSTED_PROXY_HOPS` says how many proxies stand in front; `X-Real-IP` is read only with one proxy and no `X-Forwarded-For`, which closes the way a caller could choose their own address behind a proxy that appends to `X-Forwarded-For`. For a chain whose length varies, name the proxies with `OPENOKR_TRUSTED_PROXIES` (Helm: `network.trustedProxies`), as addresses or CIDR ranges, and `X-Forwarded-For` is read from the right past them; behind a CDN that is the only way to reach the server, name the one header it writes with `OPENOKR_CLIENT_ADDRESS_HEADER` (`network.clientAddressHeader`), such as `cf-connecting-ip`. Either replaces the hop count. Every per-address limit, the sign-in hold, the session list and the `auth.rate_limited` row then count the visitor rather than the proxy. The Compose install and one ingress controller need nothing set. A malformed entry, `0.0.0.0/0`, or two of the three variables set refuse the boot naming the variable, and the chart refuses the same. The boot log says which reading is in force, a change of it writes `instance.caller_address_configured` to the instance audit chain, `openokr_caller_addresses_total` counts placed and unplaced callers, and Admin, General on a self-hosted instance says when the instance has met a visitor it could not place. On Compose, `./openokr up` hands the same list to Caddy. `docs/install/behind-a-proxy.md` says what to set for each setup.
