{{- if not .Values.secrets.existingSecret }}

Back this up now, before anything else:

  kubectl --namespace {{ .Release.Namespace }} get secret {{ printf "%s-secrets" (include "openokr.fullname" .) }} -o yaml

It holds the key every stored credential is encrypted with. This chart keeps
it across upgrades and across an uninstall, but it cannot recover it for you.
Lose it and mail passwords, channel credentials and provider keys become
unreadable.

{{- /* A named bucket is where uploads go, whatever persistence says, so the
       volume notes below are about a store the release is not using. */}}
{{- $bucket := dig "s3" "bucket" "" (.Values.storage | default dict) }}

{{- if $bucket }}

Uploaded files are kept in the S3 bucket {{ $bucket }}, so every pod reads the
same files and the replica count can change freely.
{{- else if and .Values.persistence.enabled (eq .Values.persistence.accessMode "ReadWriteOnce") }}

Uploaded files are kept on a {{ .Values.persistence.size }} ReadWriteOnce
volume, mounted at /app/storage. That volume cannot be shared across nodes, so
this release is pinned to one replica. To scale out, give storage a
ReadWriteMany class:

  --set persistence.accessMode=ReadWriteMany --set replicaCount=3
{{- end }}

{{- if and (not $bucket) (not .Values.persistence.enabled) }}

WARNING: persistence is off, so uploaded files go to an emptyDir.

They are deleted when a pod restarts, and nothing warns anybody when they go.
{{- if gt (include "openokr.mostWebReplicas" . | int) 1 }}
With {{ if include "openokr.autoscaling" . }}up to {{ end }}{{ include "openokr.mostWebReplicas" . }} replicas they are also invisible to the other
pods: a file uploaded through one pod cannot be downloaded through another, and
which pod serves a request is not something a user can influence.
{{- end }}

That is a working configuration for an instance that accepts no uploads, and a
data-loss bug for one that does. To keep files:

  --set persistence.enabled=true
{{- end }}

{{- if include "openokr.workerEnabled" . }}

The outbox relay and the scheduler run on the worker pods, the Deployment
{{ include "openokr.fullname" . }}-worker ({{ include "openokr.workerReplicas" . }} replica{{ if gt (include "openokr.workerReplicas" . | int) 1 }}s{{ end }}). The web pods only serve, and their
OPENOKR_RELAY and OPENOKR_SCHEDULER say elsewhere. Invitations, live
updates, the agents and every job on a clock wait for the worker, so read its

  kubectl --namespace {{ .Release.Namespace }} logs deploy/{{ include "openokr.fullname" . }}-worker

Scrape every pod's /api/metrics rather than the Service: the job, nudge and
delivery series are counted where the work runs.
