{{- if not .Values.secrets.existingSecret }}

Back this up now, before anything else:

  kubectl --namespace {{ .Release.Namespace }} get secret {{ printf "%s-secrets" (include "openokr.fullname" .) }} -o yaml

It holds the key every stored credential is encrypted with. This chart keeps
it across upgrades and across an uninstall, but it cannot recover it for you.
Lose it and mail passwords, channel credentials and provider keys become
unreadable.
{{- end }}

{{- if and .Values.persistence.enabled (eq .Values.persistence.accessMode "ReadWriteOnce") }}

Uploaded files are kept on a {{ .Values.persistence.size }} ReadWriteOnce
volume, mounted at /app/storage. That volume cannot be shared across nodes, so
this release is pinned to one replica. To scale out, give storage a
ReadWriteMany class:

  --set persistence.accessMode=ReadWriteMany --set replicaCount=3
{{- end }}

{{- if not .Values.persistence.enabled }}

WARNING: persistence is off, so uploaded files go to an emptyDir.

They are deleted when a pod restarts, and nothing warns anybody when they go.
{{- if gt (int .Values.replicaCount) 1 }}
With {{ .Values.replicaCount }} replicas they are also invisible to the other
pods: a file uploaded through one pod cannot be downloaded through another, and
which pod serves a request is not something a user can influence.
{{- end }}

That is a working configuration for an instance that accepts no uploads, and a
data-loss bug for one that does. To keep files:

  --set persistence.enabled=true
{{- end }}

{{- if eq .Values.mail.transport "console" }}

Mail is written to the pod log rather than sent. That is a working default,
not an error: password reset links still work, you just read them with
`kubectl logs`. Configure mail.* when you want real email.
{{- end }}
