THE METHOD IS IN THE PRODUCT

One specification, compiled, running in four places at once

Because the rule engine is pure, the same code checks a draft in the browser, refuses a bad write on the server, drives the agents, and validates imported data.

In the browser

As the user types, on every keystroke

On the server

Before any write is accepted

Inside the agents

So a nudge cites the same rule a user sees

In the importer

So migrated data is judged by the same bar

A conformance suite fails the build when the specification and the code disagree, so the product cannot drift away from the method. Every coaching message carries a rule key that resolves back to the specification, so a user can open the rule and argue with it.
